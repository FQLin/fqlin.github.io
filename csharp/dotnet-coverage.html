.NET 单元测试覆盖率实战：coverlet + ReportGenerator

两条命令：dotnet test 收集覆盖数据，reportgenerator 渲染 HTML。看完即可上手，30 分钟接进现有项目。

.NET 6+ coverlet ReportGenerator 2026-08-06 发布

单项目最小闭环

前提：已经有一个 .NET 类库 MyLib 和一个 xUnit 测试项目 MyLib.Tests，测试项目 .csproj 里引用了 coverlet.collector：

dotnet add MyLib.Tests package coverlet.collector

第一步：跑测试，同时收集覆盖率。

dotnet test MyLib.Tests \
  /p:CollectCoverage=true \
  /p:CoverletOutputFormat=opencover \
  /p:CoverletOutput=./TestResult/

三个参数含义：

  • CollectCoverage=true：让 coverlet 接管测试过程
  • CoverletOutputFormat=opencover：输出 OpenCover 格式（与 ReportGenerator 对接）
  • CoverletOutput：输出目录

跑完之后 TestResult/ 下会出现 coverage.opencover.xml。

第二步：装 ReportGenerator 工具（一次性）：

dotnet new tool-manifest
dotnet tool install dotnet-reportgenerator-globaltool

第三步：把 XML 渲染成可读的 HTML：

dotnet reportgenerator \
  "-reports:TestResult/coverage.opencover.xml" \
  "-targetdir:coveragereport" \
  -reporttypes:Html

打开 coveragereport/index.htm，即可在浏览器里看到每个类、每个方法的覆盖情况。

多测试项目合并

真实项目通常有多个测试工程（单元测试、集成测试、契约测试）。要把它们的结果合并到同一份报告：

# 1. 第一个项目：输出 JSON
dotnet test MyLib.UnitTests \
  /p:CollectCoverage=true \
  /p:CoverletOutputFormat=json \
  /p:CoverletOutput=./TestResult/

# 2. 后续项目：合并到上一个 JSON
dotnet test MyLib.IntegrationTests \
  /p:CollectCoverage=true \
  /p:CoverletOutputFormat=json \
  /p:MergeWith=TestResult/coverage.json \
  /p:CoverletOutput=./TestResult/

# 3. 最后再转一次 OpenCover 给 ReportGenerator
dotnet test MyLib.ContractTests \
  /p:CollectCoverage=true \
  /p:CoverletOutputFormat="json,opencover" \
  /p:CoverletOutput=./TestResult/

# 4. 渲染报告
dotnet reportgenerator \
  -reports:TestResult/*.xml \
  -targetdir:coveragereport \
  -reporttypes:Html
MergeWith 会把当前结果叠加到指定 JSON；最后一个项目同时输出 json 与 opencover，让 ReportGenerator 能直接吃。

阈值与门禁

仅做覆盖率统计没意义——CI 上要卡阈值，没达标直接挂掉。coverlet 支持按行 / 按分支卡阈值：

dotnet test MyLib.Tests \
  /p:CollectCoverage=true \
  /p:CoverletOutputFormat=opencover \
  /p:CoverletOutput=./TestResult/ \
  /p:Threshold=80 \
  /p:ThresholdType=line \
  /p:ThresholdStat=total

常用参数：

  • Threshold=80：目标覆盖率 80%
  • ThresholdType=line | branch | method | class：按哪种粒度卡
  • ThresholdStat=total | module | namespace | class | method：在哪一层应用阈值
阈值别一刀切。基础设施/通用组件应当要求 80%+，业务实现类可以放宽到 50%；用 ExcludeByAttribute / ExcludeByFile 把生成的代码、迁移文件排除。

断言库搭配

覆盖率只告诉你"跑了哪些代码"，不告诉你"测得对不对"。建议同时配一个表达力强的断言库：

  • xUnit 自带：Assert.Equal，够用但啰嗦。
  • FluentAssertions（社区主流）：result.Should().Be(42)，断言失败时错误信息更友好。
  • Shouldly（轻量替代）：与 FluentAssertions 类似但 API 更紧凑。
// FluentAssertions 写法
result.Should().BeOfType<Order>()
    .Which.Total.Should().Be(199m);

// xUnit 原生写法
Assert.IsType<Order>(result);
Assert.Equal(199m, ((Order)result).Total);

使用准则

  1. 覆盖率是信号，不是目标。100% 覆盖也能写出没用的测试。
  2. 新写的代码必须在合并前跑过覆盖率；老代码逐步抬阈值，不要一步到位。
  3. 把 coveragereport/ 加进 .gitignore，避免污染仓库。
  4. CI 上传 coverage.opencover.xml 给 Codecov / Coveralls，可以做趋势图与 PR 评论。
