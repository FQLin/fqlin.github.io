TrackedDeviceGraphicRaycaster 官方文档中文注释版

本文档仅围绕 Unity 官方 tracked-device-graphic-raycaster.md 进行翻译和注释。

文档来源

  • Unity 包版本：com.unity.xr.interaction.toolkit 3.4.1
  • 官方原文：

Library/PackageCache/com.unity.xr.interaction.toolkit@4612b35e2aac/Documentation~/tracked-device-graphic-raycaster.md

1. 它是什么

官方原意翻译

Tracked Device Graphic Raycaster 组件允许你使用 3D 跟踪设备，在 Canvas 上高亮并选中 UI 元素。

你需要把它添加到和 Canvas 组件同一个 GameObject 上。

更容易理解的注释

这句话可以直接理解成：

它是“让 XR 控制器射线真正能点到 Unity UI”的关键桥梁。

如果少了它，就算：

  • Canvas 是 World Space
  • 你有 NearFarInteractor
  • 你有 XRUIInputModule

也很可能还是点不到按钮。

2. 官方属性表中文翻译

属性中文说明更容易理解的注释
Ignore Reversed Graphics启用后，射线会忽略背向射线源的 Graphic。UI 背面通常不该被点到。
Check for 2D Occlusion如果 2D 对象遮挡了 Canvas，射线是否应被阻挡。对象必须有 Collider。2D 物体能不能挡住 UI。
Check for 3D Occlusion如果 3D 对象遮挡了 Canvas，射线是否应被阻挡。对象必须有 Collider。3D 物体能不能挡住 UI。
Blocking Mask允许遮挡 Canvas 的物体层。决定哪些层的对象可以挡住 UI。
Raycast Trigger Interaction检查 3D 遮挡时，Trigger Collider 是否算阻挡。Trigger 是否也当作遮挡体。

3. 对当前项目最重要的理解

它解决的不是“UI 显示”

它解决的是：

  • 射线能不能打到 UI
  • UI 能不能收到 XR 射线事件
  • 悬停、点击、滚动能不能工作

它必须和 Canvas 同物体

这点特别容易忘。

正确做法是：

  • Canvas
  • TrackedDeviceGraphicRaycaster

挂在同一个 GameObject 上。

它和 NearFarInteractor 是配套关系

可以这样记：

  • NearFarInteractor 负责发出 XR UI 射线
  • TrackedDeviceGraphicRaycaster 负责让 Canvas 接得住这条射线

缺一边都不行。

4. 遮挡选项怎么理解

Check for 3D Occlusion

适合场景：

  • UI 面板前面可能会有 3D 模型
  • 你希望“前面的物体挡住后面的 UI”

代价：

  • 增加额外检测
  • 会有性能成本

Check for 2D Occlusion

适合场景：

  • 你真的用了 2D 物理对象遮挡 UI

对当前项目，一般重要性低于 3D 遮挡。

Blocking Mask

这个参数很实用。

它决定：

  • 哪些层的对象能挡住你的 UI

如果你发现：

  • 明明开了 3D 遮挡，结果模型还是挡不住 UI

就要检查模型所在层是否在 Blocking Mask 里。

5. 官方 Architecture notes 的人话解释

官方补充了一个比较底层的实现说明，核心意思是：

  • 它在一次 UI 射线检测里，会用到“全局共享结果列表”
  • 也会用到“当前这个 Raycaster 自己的本地命中缓存”

更容易理解地说：

  • Unity EventSystem 会把很多 Raycaster 的命中结果汇总到一起
  • 所以不能简单地认为“全局结果列表第一个命中就是当前 Canvas 自己最该处理的命中”
  • TrackedDeviceGraphicRaycaster 还会维护自己的一套本地命中数据，来保证当前 Canvas 的判断更准确

这部分对日常使用不是必须掌握，但它解释了一个问题：

当场景里有多个 Canvas、多个射线器时，为什么这个组件仍然能比较稳定地区分“当前该点的是谁”。

6. 在当前项目里的配置建议

Home 场景

  • 首页按钮所在的 HomeCanvas 必须挂它
  • 如果首页始终在头前，通常可以先不开复杂遮挡

质量评价 / JND 场景

  • 如果这些场景的 UI 面板可能被模型遮挡，可以考虑开启 Check for 3D Occlusion
  • 但要结合性能和层级做测试

7. 快速排错清单

如果你在 VR 里点不到按钮，优先检查：

  1. Canvas 是否为 World Space
  2. TrackedDeviceGraphicRaycaster 是否和 Canvas 在同一个对象上
  3. 场景里是否有 XRUIInputModule
  4. NearFarInteractor.Enable UI Interaction 是否开启
  5. UI Press Input 是否绑定
  6. 是否被 3D 物体遮挡或错误遮挡

8. 一句话结论

TrackedDeviceGraphicRaycaster 是 XR UI 链路里的关键接收端。
没有它，XR 控制器射线往往“看起来对着按钮”，但按钮并不会真正响应。
