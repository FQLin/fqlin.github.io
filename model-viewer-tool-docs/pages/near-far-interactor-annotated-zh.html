1. NearFarInteractor 是什么

官方原意翻译

NearFarInteractor 是一种同时使用“近距离交互探测器”和“远距离交互探测器”的 Interactor。它可以在不同交互方式之间进行平滑切换，同时还能利用远距离交互探测器的数据与 UGUI 进行交互。

这个 Interactor 在设计上强调模块化和可扩展性。高级开发者可以实现自定义的近距离探测器和远距离探测器，它们分别需要遵循 IInteractionCaster 和 ICurveInteractionCaster 接口。

IInteractionAttachController 接口允许开发者实现自定义的附着控制器，用来控制 attach transform 的平移和旋转。默认实现支持基于距离的速度缩放，可以在远距离时把物体拉向用户，同时兼容手势跟踪和控制器跟踪。

为了配合这个 Interactor，官方还提供了一个可视化控制组件 CurveVisualController。它通过 ICurveInteractionDataProvider 接口获取曲线所需的数据，从而以更灵活的方式把交互曲线显示出来。

这个 Interactor 旨在整合 XRDirectInteractor 和 XRRayInteractor 的功能，但目前有两个需要注意的缺口：

  • 对于移动端 AR 设备，仍然需要 XRRayInteractor 来做 AR 数据射线检测，因为 NearFarInteractor 目前还不支持这个用例。
  • 官方文档这里写的是：NearFarInteractor 还不支持像 XRRayInteractor 那样直接使用摇杆控制 attach transform 的平移、旋转和缩放。

更容易理解的注释

  • 你可以把它理解成“新版统一交互器”。
  • 老思路通常是：

一个 XRDirectInteractor 负责近距离抓取，
一个 XRRayInteractor 负责远距离射线。

  • 新思路则是：

一个 NearFarInteractor 统一管理近距、远距、UI 点击，以及远距离选中后的附着逻辑。

一句人话总结：

NearFarInteractor 不是单纯的一条射线，而是一整套“近距 + 远距 + UI + 附着控制”的交互总控。

还要特别注意：

  • 它不是那条“可见的线”本身。
  • 线的视觉通常由 CurveVisualController + LineRenderer 负责。
  • 真正决定“能不能选中目标”的，是 NearFarInteractor 和它挂接的各种 Caster。

2. 官方属性表中文翻译 + 注释

属性官方含义翻译更容易理解的注释
Interaction Manager当前 Interactor 要通信的 XR Interaction Manager。如果为空，会自动寻找。一般就是场景里的总交互管理器。大多数情况下可以留空，让系统自己找。
Interaction Layer Mask只允许与交互层有重叠的 Interactable 发生交互。这是 XR 的“交互层”，不是普通的 Unity Layer。能不能选中对象，先看这里匹不匹配。
Select Action Trigger定义选中状态如何由输入触发，例如按住、悬停时按下、切换式开关、粘性切换等。简单理解就是：扳机的“选中”到底是按住生效，还是点一下切换生效。
Keep Selected Target Valid首次选中后，即使不再触碰或指向目标，也继续保持选中。建议抓取物体时为 true，传送时为 false。做抓取类交互时通常建议开着，不然手一抖或射线偏一下就掉选中。
Allow Hovered Activate当当前没有选中对象时，允许对“仅悬停”的对象发送激活和取消激活事件。这个更像“次级动作”开关。一般初期可以先保持默认。
Target Priority Mode指定 Targets For Selection 中应该追踪多少个目标，适合自定义反馈，选项按性能从高到低排列。只有你做复杂提示逻辑时才需要深究。大多数情况下先用默认值。
Starting Selected Interactable启动时自动选中的 Interactable，可为空。一般不用。除非你想让某个东西一开场就被“拿在手里”。
Parent Interactable可选的父级 Interactable 依赖，用于决定处理顺序。偏高级用法。当前项目通常不用手配。
Auto Find Parent Interactable注册到管理器时，是否自动向上查找父级 Interactable。关闭后可手动设置，以提高启动性能。默认开着更省心。只有你明确要做极致优化时再关。
Interaction Attach Controller控制 attach transform 的附着控制器引用。这是“远距离选中后物体怎么跟着走”的关键组件。
Enable Near Casting是否启用近距离探测器。默认 true。开了以后，手靠近物体时就能走近距离交互。
Near Caster近距离交互探测组件，必须实现 IInteractionCaster。常见默认实现是 SphereInteractionCaster，也就是在手附近做球形探测。
Sorting Strategy近距离探测命中的目标如何排序。可选 None、SquareDistance、InteractableBased、ClosestPointOnCollider。目标很多时，决定“优先选谁”。默认策略通常够用。
Sort Near Targets After Target Filter是否在目标过滤后再对近距目标排序。仅当设置了 target filter 且 filter 本身不排序时有意义。先不用动。属于偏深入的排序细节。
Enable Far Casting是否启用远距离探测器。默认 true。开了以后，才能打出射线或曲线去点远处 UI / 模型。
Far Caster远距离交互探测组件，必须实现 ICurveInteractionCaster。常见默认实现是 CurveInteractionCaster。
Far Attach Mode远距离选中时，附着点应该如何调整。通常决定物体是留在远处，还是被拉到手边。这是非常关键的体验开关。对于点云展示，通常更适合 Far。
UI Interaction是否允许该 Interactor 与 UI 元素交互。默认 true。要点 World Space Canvas 上的按钮，这里必须开。
Block UI On Interactable Selection当已经选中了一个 Interactable 时，是否阻止 UI 交互。默认 true。防止“抓着模型时顺手又误点了 UI”。实验项目里通常建议保留 true。
UI Press Input用于按下 UI 元素的输入，类似鼠标左键。实现为 XRInputButtonReader。这个决定了你拿射线对准按钮后，用哪个按键算“点击”。
UI Scroll Input用于滚动 UI 的输入，类似鼠标滚轮。实现为 XRInputValueReader<Vector2>。如果面板里以后有滚动列表，这个才更重要。
Select Input用于选中 Interactable 的输入。一般对应扳机或 Grip。
Activate Input用于激活 Interactable 的输入，可触发对象的次级动作。可以理解成“选中之外的第二个动作键”。
Interactor Filters参见官方的 Interaction Filters 页面。用于进一步控制“哪些目标可以被交互”，属于进阶功能。
Interactor Events参见官方的 Interactor Events 页面。主要用于在 Inspector 里挂事件回调。

3. 官方枚举说明中文翻译 + 注释

3.1 Region

官方含义：由 selectionRegion 属性使用，用来表示当前选择发生在近距离区域还是远距离区域。

  • None：当前没有发生选择。
  • Near：当前通过近距离交互发生选择。
  • Far：当前通过远距离交互发生选择。

更容易理解的注释：

  • 这是系统在内部标记“这次交互属于近距还是远距”。
  • 如果后面你要做不同提示效果，例如近距离时显示抓取提示、远距离时显示射线提示，这个状态会很有用。

3.2 NearCasterSortingStrategy

官方含义：定义近距离探测发现多个有效目标时，该如何排序。

  • None：不排序。
  • SquareDistance：按 Interactor 与 Interactable 附着点的平方距离排序，效率最高。
  • InteractableBased：按 Interactable 自身定义的排序策略排序，通常与 Collider 有关。
  • ClosestPointOnCollider：按 Interactor 附着点与目标 Collider 最近点之间的平方距离排序，适合高精度区分。

更容易理解的注释：

  • 当手附近同时挨着多个物体时，系统必须决定“优先算你碰到谁”。
  • 如果你的场景里只会同时接近一两个对象，默认通常已经足够。
  • 如果以后 JND/质量评价场景里模型周围放了很多小控件，才需要认真调这个。

3.3 InteractorFarAttachMode

官方含义：控制远距离选中时，Interactor 默认如何调整自己的 attach transform。

  • Near：把 attach transform 重置到近处点位。通常会导致物体被拉到手边。
  • Far：把 attach transform 移动到远处命中点。通常会导致物体留在远处命中位置。

官方补充：某些 Interactable，例如实现了 IFarAttachProvider 接口的 XR Grab Interactable，可以覆盖 Interactor 的默认行为。它们默认会参考 Interactor 的偏好值，但也可以强制使用 Near 或 Far。

更容易理解的注释：

  • Near 更像“远处抓住后直接拉到手里”。
  • Far 更像“远处点到它，但它还待在原地，只是被你远程操控”。
  • 对当前点云实验项目，通常推荐 Far，因为我们更希望模型留在展示位置，而不是突然飞到用户脸前。

4. 官方 Usage 部分中文翻译 + 注释

官方原意翻译

这个组件应该挂载到一个在交互系统中充当 Interactor 的 GameObject 上。为了拥有完整功能，它需要：

  • 一个实现 IInteractionAttachController 的组件
  • 一个实现 IInteractionCaster 的近距离探测组件
  • 一个实现 ICurveInteractionCaster 的远距离探测组件

如果 Interaction Attach Controller、Near Caster 或 Far Caster 的引用为空，运行时会自动添加这些接口的默认实现组件。

更容易理解的注释

  • 官方确实支持“如果你没配，它运行时帮你补默认组件”。
  • 但对当前项目来说，不建议依赖这个自动补全行为。

原因很简单：

  • 运行时自动补，编辑器里不直观。
  • 你在 Inspector 里很难一眼看清“现在到底是谁在起作用”。
  • 出问题时排查会更绕。

所以更推荐的做法是：

直接使用 Starter Assets 自带的 Left_NearFarInteractor / Right_NearFarInteractor 预制结构，或者显式把这些组件挂好并绑定引用。

5. 相关组件补充说明

这一节不是逐字翻译，而是把与 NearFarInteractor 关系最紧密的几个官方组件，用更贴近项目的方式说明清楚。

5.1 InteractionAttachController

官方原意翻译总结：

  • 这是 IInteractionAttachController 的默认实现。
  • 它和 NearFarInteractor 配合使用，用于处理远距离交互、已选中物体的稳定，以及把远处物体以加速方式拉向用户。
  • 它还支持一种相对于 XROrigin 的平滑模式，可以让远距离抓取的物体在玩家移动时保持更稳定的运动表现。
  • 默认配置下，平滑和稳定主要只影响“带偏移”的远距离抓取对象，从而保证回到近距离交互时，物体相对手或控制器的延迟尽量小。

更容易理解的注释：

  • 如果把 NearFarInteractor 理解成“总指挥”，那 InteractionAttachController 就是“物体跟随规则的执行者”。
  • 它决定了远距离选中后，物体是更稳、更平滑，还是更灵敏。
  • 在点云实验里，如果模型远距离选中后抖动明显，或者拉近/推远的体验怪怪的，通常就该先检查这个组件。

几个最值得优先理解的参数：

参数更容易理解的注释
Transform To Follow附着点要跟随谁。通常是控制器或某个稳定锚点。
Motion Stabilization Mode是否对附着点做稳定处理。稳定后会更“稳”，但也可能略微没那么“跟手”。
Smooth Offset是否平滑远距离偏移。适合让远程抓物更自然。
Use Distance Based Velocity Scaling距离越远，移动速度可以越快，避免远距离推拉太肉。
Use Manipulation Input是否允许通过输入轴控制附着点。
Manipulation Input具体是哪组输入轴在操控附着点。
Translate Speed推拉速度。
Rotate Speed旋转速度。

补充说明：

虽然 near-far-interactor.md 里写“NearFarInteractor 还不支持像 XRRayInteractor 那样用摇杆直接控制 attach transform”，但当前 3.4.1 Starter Assets 里的实际方案，已经把这部分操控更多地下沉到了 InteractionAttachController 的 Manipulation Input 上。所以从工程实践看，仍然可以通过整套预制件配置实现远距离对象操控。

5.2 CurveInteractionCaster

更容易理解的注释：

  • 这是远距离探测器。
  • 它负责真正把“远程射线/曲线”打出去，看击中了什么。
  • 它支持多种命中方式，例如 Raycast、SphereCast、ConeCast。
  • 在 Starter Assets 里，它通常不只是“直直一条激光”，而是允许更柔和、更好看的交互曲线。

对当前项目的意义：

  • 你要点首页按钮，它会参与。
  • 你要远程选中点云模型，它也会参与。
  • 所以它是“远距离交互命中逻辑”，不是“纯视觉线条”。

5.3 SphereInteractionCaster

更容易理解的注释：

  • 这是近距离探测器。
  • 它通常在手附近做球形检测，用来判断“现在有没有碰到附近可交互物体”。
  • 如果你以后想支持“手靠近某个物体就能抓”，它就很重要。

5.4 CurveVisualController

官方原意翻译总结：

  • 它是一个用于控制 LineRenderer 的可视化控制器。
  • 它根据实现了 ICurveInteractionDataProvider 的数据源提供的信息，生成一条可视化曲线。
  • 它可以根据当前命中状态、UI 状态、选中状态等，动态改变线的颜色、宽度、弯曲程度、材质等。

更容易理解的注释：

  • 它只负责“把线画出来，并画得更聪明”。
  • 它不负责真正的交互命中。
  • 所以如果你看到线在，但点不到按钮，优先检查的是 NearFarInteractor、CurveInteractionCaster、Canvas 配置、输入动作，而不是先怪 CurveVisualController。

6. XR UI 官方要求，和本项目最相关的部分

根据官方 ui-setup.md 和 tracked-device-graphic-raycaster.md，要让 XR 控制器和 Unity UI 正常交互，至少要满足下面这条链路：

6.1 Canvas 必须是 World Space

  • XR Interaction Toolkit 只能与 Render Mode = World Space 的 Canvas 交互。
  • 如果还是 Screen Space - Overlay 或 Screen Space - Camera，XR 射线通常不会按你预期工作。

6.2 Canvas 上要有 Tracked Device Graphic Raycaster

  • 这个组件要和 Canvas 挂在同一个 GameObject 上。
  • 它的作用是让 3D 跟踪设备的射线可以高亮和点击 Canvas 上的 UI。

几个容易理解的参数：

参数更容易理解的注释
Ignore Reversed Graphics射线是否忽略背对自己的 UI 面。
Check for 2D Occlusion2D 物体能不能挡住 UI 射线。
Check for 3D Occlusion3D 物体能不能挡住 UI 射线。
Blocking Mask哪些层的物体允许挡住 UI 射线。
Raycast Trigger InteractionTrigger Collider 是否也算遮挡物。

性能提醒：

  • 官方明确说明，Check for 2D Occlusion 和 Check for 3D Occlusion 默认关闭，是为了省性能。
  • 每开一个，就会增加额外射线检测。

6.3 场景里要有 EventSystem + XRUIInputModule

  • 场景里只能有一个有效的 EventSystem。
  • 同一时刻也只应该有一个启用中的 Input Module。
  • 如果是 XR UI 交互，应使用 XRUIInputModule 这一套，而不是旧的 Standalone Input Module。

6.4 NearFarInteractor 本身要启用 UI 交互

  • Enable UI Interaction 必须开启。
  • UI Press Input 要正确绑定。
  • 否则即使射线打到按钮上，看起来像对准了，也不会真正“点下去”。

7. 在当前项目里应该怎么用

这一节不是官方原文，而是结合当前 VR 点云实验项目给出的落地建议。

7.1 首页场景 Home

目标：

  • 用控制器射线点按钮
  • 面板跟随视角
  • 暂时不强调近距离抓物

建议：

  • 保留 NearFarInteractor
  • Enable UI Interaction = true
  • Enable Far Casting = true
  • Enable Near Casting 可以先开着，也可以按需求关闭
  • Canvas 用 World Space
  • Canvas 上挂 TrackedDeviceGraphicRaycaster
  • 场景里使用 EventSystem + XRUIInputModule

一句人话总结：

首页主要把 NearFarInteractor 当成“XR UI 射线点击器”来用。

7.2 质量评价场景 Quality Rating

目标：

  • 远距离点 UI
  • 远距离选中模型
  • 对模型进行旋转、缩放、重置等操作

建议：

  • Enable Near Casting = true
  • Enable Far Casting = true
  • Far Attach Mode = Far
  • 模型根对象有 Collider
  • 模型根对象挂 XRGrabInteractable 或项目中自己的可交互逻辑
  • 如果你希望模型留在展示位置，不要让它瞬间飞到手边

一句人话总结：

对质量评价场景，Far 模式通常比 Near 模式更符合实验展示逻辑。

7.3 JND 场景

目标：

  • 与质量评价场景类似，但更多偏向点选、对比、确认

建议：

  • 大体沿用质量评价场景的配置思路
  • 如果主要是比较和确认，而不是自由抓取模型，那么更应该优先保证 UI 点击和远距离稳定选中

8. 最容易踩的坑

8.1 把 XR 交互层和 Unity 物理层混为一谈

这是最常见的误区之一。

  • Interaction Layer Mask 管的是“XR 交互逻辑允许不允许”
  • Physics Layer Mask / Raycast Mask 管的是“物理射线能不能先打中 Collider”

所以会出现两种典型问题：

  • 射线明明碰到 Collider 了，但选不中

原因通常是 XR 交互层不匹配

  • 对象明明挂了 XRGrabInteractable，但射线像穿过去一样

原因通常是 Collider 层没有被 Caster 的物理 LayerMask 包含

8.2 只有线，没有交互

常见原因：

  • CurveVisualController 在工作，但 NearFarInteractor 的输入没配好
  • Enable UI Interaction 没开
  • Canvas 不是 World Space
  • TrackedDeviceGraphicRaycaster 没挂
  • 场景里没有 XRUIInputModule

8.3 有 UI 交互，但 3D 模型点不到

常见原因：

  • 模型没有 Collider
  • 模型只有 Mesh，没有可命中的 Collider
  • 模型根对象没有 XRGrabInteractable
  • Interaction Layer Mask 不匹配

8.4 远距离抓取体验不对

常见现象：

  • 物体突然飞到脸上
  • 物体选中后抖动
  • 旋转或推拉手感怪

优先检查：

  • Far Attach Mode
  • InteractionAttachController
  • 模型刚体、碰撞体和附着点设置

9. 推荐的理解顺序

如果你后面继续深入，建议按这个顺序理解：

  1. 先理解 NearFarInteractor 是“总控”
  2. 再理解 CurveInteractionCaster 和 SphereInteractionCaster 是“怎么探测目标”
  3. 再理解 InteractionAttachController 是“选中后怎么跟随和操控”
  4. 最后理解 CurveVisualController 是“怎么把射线画好看”

这样学习会比一上来盯着一大堆组件参数更轻松。

10. 一句话版结论

NearFarInteractor 是 Unity 新版 XRI 里更推荐使用的统一交互器。
对当前项目来说，它最适合承担两件事：

  • 用 XR 射线点击 World Space UI
  • 用远近结合的方式选择并操控点云/模型对象

如果后面你继续沿这条路线做，建议始终围绕下面这套链路检查配置是否完整：

NearFarInteractor -> Caster -> Interactable / UI -> AttachController -> VisualController
