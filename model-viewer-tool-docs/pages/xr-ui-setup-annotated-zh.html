XR UI Setup 官方文档中文注释版

本文档仅围绕 Unity 官方 ui-setup.md 进行翻译和注释。

文档来源

  • Unity 包版本：com.unity.xr.interaction.toolkit 3.4.1
  • 官方原文：

Library/PackageCache/com.unity.xr.interaction.toolkit@4612b35e2aac/Documentation~/ui-setup.md

1. 官方核心结论

官方原意翻译

如果要与 Unity 内建 UI 元素交互，尤其是使用 3D 跟踪设备时，需要做额外配置。
XR Interaction Toolkit 提供了一些新组件和辅助菜单，可以把 XR 控制器无缝接入 UI。

更容易理解的注释

这句话可以直接翻译成人话：

普通 Unity UI 默认不是为 VR 控制器射线准备的。
如果你想让手柄射线点按钮，必须走 XR UI 这套配置链路。

2. GameObject 菜单里的辅助创建

官方说明：

你可以从 GameObject > XR 菜单里使用辅助项创建 XR UI。

UI Canvas

作用：

  • 创建一个新的 World Space Canvas
  • 如果场景里还没有 EventSystem，还会一起创建并配置 XR 用的 EventSystem

UI EventSystem

作用：

  • 创建 XR 用的 EventSystem
  • 或者修改并选中当前场景中已有的 EventSystem

更容易理解的注释

如果你是手工搭场景，这两个菜单可以帮你少漏很多关键组件。

3. Event System

官方原意翻译

Event System 是 UI 事件的中央分发器。它负责处理输入，并更新当前活动的 Canvas。每个 EventSystem 还需要一个 Input Module 来处理输入。

XR 交互器如果要支持 UI 交互，例如 NearFarInteractor 或 XRPokeInteractor，就需要向 XR UI Input Module 注册，才能与 Unity UI 组件交互。

通常会把 EventSystem 设置为 DontDestroyOnLoad，这样多个场景切换时始终只有一个 EventSystem 实例。

更容易理解的注释

这里有三个非常重要的结论：

  • 场景里同一时间只能有一个有效的 EventSystem
  • 同一时间也只应该有一个启用中的 Input Module
  • XR UI 交互时，应该用 XRUIInputModule，而不是旧的 StandaloneInputModule

对你的项目尤其重要，因为你有多个场景：

  • Home
  • Quality Rating
  • JND

后期场景切换一多，如果每个场景都自己放一个 EventSystem，很容易打架。

4. Tracked Device Physics Raycaster

官方说明：

场景里还可以添加 Tracked Device Physics Raycaster，这样带物理 Collider 的对象也能接收来自跟踪设备的 Event System 事件。

更容易理解的注释

  • 这是“让物理对象也吃到 UI 事件风格输入”的一条路径。
  • 但对你现在的项目来说，更常见的主线还是：

NearFarInteractor -> World Space Canvas -> TrackedDeviceGraphicRaycaster -> XRUIInputModule

5. Canvas

官方原意翻译

所有 UI 元素都存在于 Canvas 中。
在 XR Interaction Toolkit 里，用户只能与 Render Mode = World Space 的 Canvas 交互。

XR Interaction Toolkit 还提供了一个新组件 Tracked Device Graphic Raycaster，它允许 3D 跟踪设备高亮并选中这个 Canvas 上的 UI 元素。

更容易理解的注释

这部分最重要的结论只有一句：

XR 控制器要点 UI，Canvas 必须是 World Space。

如果还是：

  • Screen Space - Overlay
  • Screen Space - Camera

那通常不会符合你想要的 VR UI 交互方式。

6. UI 遮挡检测

官方原意翻译

当使用 Tracked Device Graphic Raycaster 时，可能会出现非 UI 物体挡在 UI 前面的情况。
为了支持“前面的物体应该挡住后面的 UI”这种自然行为，可以启用：

  • Check For 3D Occlusion
  • Check For 2D Occlusion

官方提醒

这两个选项默认关闭，是为了节省性能。
因为每启用一个，就会增加额外的射线检测成本。

更容易理解的注释

如果你发现：

  • 面板明明被模型挡住了，但手柄射线还能穿过去点到按钮

那就应该考虑遮挡检测配置。

但如果你当前项目里 UI 面板总是放在视野前方、前面也没有复杂遮挡，那可以先不急着开。

7. Canvas Optimizer

官方说明：

Canvas Optimizer 是可选组件，用于降低层级很深、UI 很复杂时的性能开销。
它还会自动禁用那些看不见或距离太远的 Canvas 的输入处理。

更容易理解的注释

当前这个项目的 UI 还没有复杂到必须马上上它。
但如果后面：

  • 面板越来越多
  • 多场景都挂了不少 World Space Canvas
  • VR 设备上 UI 性能开始变差

它会变得有价值。

8. Known Issues with Input Fields

官方提到两个已知问题：

  • UWP 平台上，标准 uGUI 的 Input Field 可能收不到软件键盘输入，建议用 TextMeshPro - Input Field
  • Quest 平台上，使用 Multi Line Newline 的 Input Field 可能会有软件键盘关闭问题

更容易理解的注释

你当前项目的首页、评分、JND 选择目前并不依赖文本输入，所以这部分不是第一优先级。
但以后如果你要做：

  • 路径输入
  • 实验编号输入
  • 被试信息录入

就最好直接优先选 TMP 输入框。

9. 对当前项目的最简落地链路

如果你只想记最实用的一条链路，就记这个：

  1. Canvas.RenderMode = World Space
  2. Canvas 上有 TrackedDeviceGraphicRaycaster
  3. 场景里有 EventSystem + XRUIInputModule
  4. 控制器上用 NearFarInteractor
  5. NearFarInteractor.Enable UI Interaction = true
  6. UI Press Input 已正确绑定

10. 一句话结论

XR UI 不是“普通 Unity UI 自动就能用”的。
对这个项目来说，XR UI 是否正常，核心就看：

World Space Canvas + TrackedDeviceGraphicRaycaster + XRUIInputModule + NearFarInteractor
