XR Origin (XR Rig) 预置件分析

本文档用于解释 XR Interaction Toolkit Starter Assets 中的 XR Origin (XR Rig) 预置件，重点面向当前这个“VR 点云主观实验平台”项目。

预置件路径：

Assets/Samples/XR Interaction Toolkit/3.4.1/Starter Assets/Prefabs/XR Origin (XR Rig).prefab

重要说明：

我检查磁盘上已保存的 HomeScene.unity 时，看到旧的手工 XR Origin 仍然在场景中，也看到一个被禁用的 XR Interaction Simulator 实例；但当时没有在已保存的场景文件里看到 XR Origin (XR Rig) 这个预置件实例。如果你是在 Unity 编辑器中刚拖入但还没有保存场景，那么它只存在于编辑器当前状态中，文本文件里暂时看不到。本文档主要分析 XRI 官方预置件本体。如果你保存场景后，我可以继续帮你检查“场景实例”的具体参数覆盖。

1. 这个预置件是做什么的

XR Origin (XR Rig) 是 XR Interaction Toolkit 提供的标准 XR 玩家 rig。它不是一个单纯的摄像机对象，而是一整套 VR 玩家基础结构。

它包含的能力有：

  • 头显位置和旋转追踪。
  • 左右手柄位置和旋转追踪。
  • 远距离射线式交互。
  • 近距离触碰式交互。
  • 传送交互。
  • 可选的凝视交互。
  • 连续移动、快速转向、平滑转向、重力、攀爬、跳跃、抓取移动等 Locomotion 功能。
  • 自动启用 XRI 默认输入动作资源。
  • 使用 CharacterController 表示玩家身体碰撞。

对当前项目来说，它适合作为新项目的 VR 基础。因为它和 Unity 6000.x、XR Interaction Toolkit 3.x 的使用方式更一致，比我们手工一点点拼 XR Origin 更适合作为学习和长期维护的基础。

│  │  ├─ Poke Interactor

│  │  ├─ Teleport Interactor
│  │  └─ Near-Far Interactor
│  ├─ Left Controller Teleport Stabilized Origin
│  │  └─ Left Controller Stabilized Attach
│  ├─ Right Controller
│  │  ├─ Right Controller Visual
│  │  ├─ Poke Interactor
│  │  │  └─ Poke Point Affordances
│  │  ├─ Teleport Interactor
│  │  └─ Near-Far Interactor

可以先这样理解：

  • XR Origin (XR Rig) 是玩家在 Unity 世界中的根对象。
  • Camera Offset 是头显和手柄追踪对象的父节点。
  • Main Camera 代表用户的头显视角。
  • Left Controller 和 Right Controller 代表左右 VR 手柄。
  • 每个手柄下面的 Interactor 是不同的交互方式。
  • Locomotion 下面放的是移动、转向、传送、重力、跳跃等能力。

3. 根对象：XR Origin (XR Rig)

GameObject

名称：

XR Origin (XR Rig)

状态：

  • 默认激活。
  • Layer 是 2，也就是 Unity 内置的 Ignore Raycast 层。

为什么使用 Ignore Raycast：

  • 玩家 rig 通常不应该被自己的射线打到。
  • 如果以后在 rig 下添加可见模型或碰撞体，要小心不要让它们挡住 UI 射线或点云选择射线。

Transform

关键参数：

  • Local Position：{x: 0, y: 0, z: 0}
  • Local Rotation：单位旋转
  • Local Scale：{x: 1, y: 1, z: 1}
  • 子节点：Camera Offset、Locomotion

作用：

  • 这是玩家在场景中的总根节点。
  • 移动或旋转它，会带动头显、手柄、交互器和移动系统一起变化。

XROrigin 组件

脚本：

Unity.XR.CoreUtils.XROrigin

主要参数：

  • Camera：引用 Main Camera。
  • Origin Base Game Object：引用根对象 XR Origin (XR Rig)。
  • Camera Floor Offset Object：引用 Camera Offset。
  • Requested Tracking Origin Mode：0。
  • Camera Y Offset：1.36144。

作用：

  • 把真实 XR 设备的追踪空间映射到 Unity 场景空间。
  • 告诉系统哪一个 Camera 是头显相机。
  • 在需要的时候通过 Camera Offset 调整相机高度。

对当前项目的建议：

  • 每个场景只保留一个激活的 XROrigin。
  • 不要让旧的手工 XR Origin 和新的 XRI XR Origin (XR Rig) 同时激活。
  • 如果两个都激活，可能出现两个相机、两个 AudioListener、重复输入、UI 射线混乱等问题。

CharacterController 组件

这是 Unity 内置组件，不是 XRI 专属脚本。

主要参数：

  • Height：1.36144
  • Radius：0.1
  • Slope Limit：45
  • Step Offset：0.5
  • Skin Width：0.08
  • Min Move Distance：0.001
  • Center：{x: 0, y: 0.76072, z: 0}
  • Is Trigger：false

作用：

  • 给玩家 rig 一个胶囊形碰撞体。
  • 连续移动、重力、攀爬、跳跃等系统可以用它来做碰撞和地面检测。

参数解释：

  • Height 表示玩家身体碰撞高度。
  • Radius 表示玩家身体碰撞半径。
  • Slope Limit 表示能走上去的最大坡度。
  • Step Offset 表示可跨越的台阶高度。
  • Skin Width 是碰撞计算的容差。
  • Min Move Distance 表示小于这个数值的移动会被忽略。
  • Center 是胶囊碰撞体在本地坐标中的中心。

对当前项目的建议：

  • 如果实验只需要固定位置观察点云，可以先保留这个组件，但禁用不需要的移动能力。
  • 如果以后完全不允许移动，它可以保留但不一定发挥作用。

InputActionManager 组件

脚本：

UnityEngine.XR.Interaction.Toolkit.Inputs.InputActionManager

主要参数：

  • Action Assets：引用 XRI Default Input Actions。

作用：

  • 当 rig 激活时，自动启用输入动作资源。
  • 头显追踪、手柄追踪、按钮、移动、转向、传送、UI 滚动等都依赖这些输入动作。

对当前项目的建议：

  • 保留这个组件。
  • 如果发现手柄没有输入、UI 点不动、头显不追踪，应该优先检查这个组件和输入动作资源。

XRInputModalityManager 组件

脚本：

UnityEngine.XR.Interaction.Toolkit.Inputs.XRInputModalityManager

主要参数：

  • Left Hand：空。
  • Right Hand：空。
  • Left Controller：引用 Left Controller。
  • Right Controller：引用 Right Controller。
  • 模式切换事件：为空。

作用：

  • 管理“手部追踪”和“控制器追踪”两种输入模式。
  • 当前预置件只配置了控制器，没有配置裸手追踪对象。

对当前项目的建议：

  • 这符合目前 Oculus/Quest 手柄项目的需要。
  • 如果以后要支持裸手追踪，再考虑补充手部对象。

XRGazeAssistance 组件

脚本：

UnityEngine.XR.Interaction.Toolkit.Interaction.Gaze.XRGazeAssistance

状态：

  • 默认禁用。

主要参数：

  • Gaze Interactor：引用 Gaze Interactor。
  • Fallback Divergence：60。
  • Hide Cursor With No Active Rays：启用。
  • Ray Interactors：包含左右传送射线。
  • Aim Assist Required Angle：30。
  • Aim Assist Required Speed：0.25。
  • Aim Assist Percent：0.8。
  • Aim Assist Max Speed Percent：10。

作用：

  • 用于辅助凝视交互。
  • 在用户通过视线选择对象时，帮助修正瞄准方向。

对当前项目的建议：

  • 先保持禁用。
  • 主观实验中，如果用户只是看某个位置就触发选择，容易产生误操作。

4. Camera Offset

路径：

XR Origin (XR Rig)/Camera Offset

组件：

  • Transform

作用：

  • 作为头显和手柄追踪对象的父节点。
  • 被 XROrigin 作为 Camera Floor Offset Object 使用。

对当前项目的建议：

  • 头显和手柄追踪对象应放在这里。
  • 如果某个 UI 要跟着玩家整体位置走，但不跟着头部转动，可以放在 XR Origin (XR Rig) 下。
  • 如果某个 UI 要永远贴在用户眼前，才应该放在 Main Camera 下。

5. Main Camera

路径：

XR Origin (XR Rig)/Camera Offset/Main Camera

组件：

  • Transform
  • Camera
  • AudioListener
  • TrackedPoseDriver

Transform

主要参数：

  • 父节点：Camera Offset
  • Local Position：{x: 0, y: 0, z: 0}
  • Local Rotation：单位旋转
  • Local Scale：{x: 1, y: 1, z: 1}

作用：

  • 它的位置和旋转由头显追踪数据驱动。
  • 通常不要手动控制这个 Transform。

Camera 组件

主要参数：

  • Clear Flags：Skybox。
  • Background Color：{r: 0.19215687, g: 0.3019608, b: 0.4745098, a: 0}。
  • Near Clip Plane：0.01。
  • Far Clip Plane：1000。
  • Field Of View：60。
  • Culling Mask：全部层。
  • Target Eye：双眼。
  • HDR：启用。
  • MSAA：启用。

作用：

  • 渲染 VR 双眼画面。

参数解释：

  • Near Clip Plane 是最近可见距离，值小有利于近距离 UI 和手柄显示。
  • Far Clip Plane 是最远可见距离。
  • Field Of View 在 XR 中通常会被头显运行时控制，这里的值更多是编辑器或非 XR 模式参考。
  • Target Eye 表示渲染到双眼。
  • Culling Mask 控制哪些层会被相机看到。

对当前项目的建议：

  • 点云可能比较大，必要时可以调整 Far Clip Plane。
  • 近距离 UI 多时，Near Clip Plane 保持较小比较合适。

AudioListener 组件

作用：

  • 从用户头部位置接收 3D 音频。

对当前项目的建议：

  • 一个场景里只能有一个激活的 AudioListener。
  • 如果旧 XR Origin 里还有相机和 AudioListener，要禁用或删除旧的。

TrackedPoseDriver 组件

脚本：

UnityEngine.InputSystem.XR.TrackedPoseDriver

主要参数：

  • Tracking Type：位置和旋转。
  • Update Type：默认更新和渲染前更新。
  • Ignore Tracking State：关闭。
  • Position Input：头显中心眼位置。
  • Rotation Input：头显中心眼旋转。
  • Tracking State Input：头显追踪状态。

作用：

  • 用真实头显追踪数据驱动 Main Camera 的位置和旋转。

对当前项目的建议：

  • 这是 VR 头显正常工作的关键组件。
  • 如果头显视角不动，优先检查这个组件和输入动作引用。

6. Left Controller 和 Right Controller

路径：

  • XR Origin (XR Rig)/Camera Offset/Left Controller
  • XR Origin (XR Rig)/Camera Offset/Right Controller

左右手柄对象的组件结构基本一致：

  • Transform
  • ControllerInputActionManager
  • XRInteractionGroup
  • HapticImpulsePlayer
  • TrackedPoseDriver

可以这样理解：

  • Left Controller / Right Controller 是真实手柄在 Unity 场景里的追踪对象。
  • 它们下面挂着可视模型、近距离触碰交互器、远距离交互器和传送交互器。
  • 它们本身负责接收手柄位姿、管理输入动作、管理手柄上的多个交互器。

ControllerInputActionManager 组件

脚本：

ControllerInputActionManager

左手柄主要参数：

  • Ray Interactor：空。
  • Near Far Interactor：引用左手 Near-Far Interactor。
  • Teleport Interactor：引用左手 Teleport Interactor。
  • Teleport Mode：左手传送模式输入动作。
  • Teleport Mode Cancel：左手取消传送输入动作。
  • Turn：左手平滑转向输入动作。
  • Snap Turn：左手快速转向输入动作。
  • Move：左手移动输入动作。
  • UI Scroll：左手 UI 滚动输入动作。
  • Smooth Motion Enabled：启用。
  • Smooth Turn Enabled：禁用。
  • Near Far Enable Teleport During Near Interaction：启用。
  • UI Scrolling Enabled：启用。

右手柄主要差异：

  • 使用右手输入动作引用。
  • Smooth Motion Enabled：禁用。
  • Smooth Turn Enabled：禁用。

作用：

  • 统一管理某只手柄上的输入动作和交互模式。
  • 决定什么时候启用近远交互、什么时候启用传送、什么时候允许移动或转向。

参数解释：

  • Ray Interactor 是旧式或简单射线交互器引用，这个预置件主要使用 NearFarInteractor，所以这里为空。
  • Near Far Interactor 是主要的 UI 和物体交互器。
  • Teleport Interactor 是专门用于传送的射线。
  • Teleport Mode 是进入传送瞄准状态的输入动作。
  • Teleport Mode Cancel 是取消传送瞄准的输入动作。
  • Turn 对应平滑转向。
  • Snap Turn 对应固定角度快速转向。
  • Move 对应连续移动。
  • UI Scroll 对应滚动 UI。
  • Smooth Motion Enabled 决定这只手是否能驱动连续移动。
  • Smooth Turn Enabled 决定这只手是否能驱动平滑转向。
  • UI Scrolling Enabled 决定这只手是否能滚动 UI。

对当前项目的建议：

  • 主观质量评价通常需要稳定观察条件，建议先禁用连续移动和传送。
  • 首页、设置页、打分页仍然需要近远 UI 交互，所以 Near Far Interactor 应保留。

XRInteractionGroup 组件

脚本：

UnityEngine.XR.Interaction.Toolkit.Interactors.XRInteractionGroup

左手主要参数：

  • Group Name：Left
  • Starting Group Members：左手 Poke Interactor、左手 Near-Far Interactor
  • Starting Interaction Overrides Map：左手 Poke Interactor 覆盖左手 Near-Far Interactor

右手主要参数：

  • Group Name：Right
  • Starting Group Members：右手 Poke Interactor、右手 Near-Far Interactor
  • Starting Interaction Overrides Map：右手 Poke Interactor 覆盖右手 Near-Far Interactor

作用：

  • 管理同一只手上的多个交互器。
  • 避免近距离触碰和远距离射线同时争抢同一个选择行为。

参数解释：

  • Group Name 是分组名称。
  • Starting Group Members 是进入场景时自动加入该组的交互器。
  • Starting Interaction Overrides Map 是交互优先级规则。

对当前项目的建议：

  • 保留这个组件。
  • 它可以减少 UI 触碰、远程射线、点云选择之间的冲突。

HapticImpulsePlayer 组件

脚本：

UnityEngine.XR.Interaction.Toolkit.Inputs.Haptics.HapticImpulsePlayer

主要参数：

  • Haptic Output：左手或右手触觉输出动作。
  • Amplitude Multiplier：1。

作用：

  • 让手柄震动。
  • 可用于按钮点击反馈、选择反馈、错误提示等。

参数解释：

  • Haptic Output 指向对应手柄的震动输出。
  • Amplitude Multiplier 是震动强度倍数。

对当前项目的建议：

  • 可以保留，但不一定要使用。
  • 主观实验中震动可能干扰受试者感受，如果不需要可以不主动调用。

手柄上的 TrackedPoseDriver 组件

脚本：

UnityEngine.InputSystem.XR.TrackedPoseDriver

主要参数：

  • Tracking Type：位置和旋转。
  • Update Type：默认更新和渲染前更新。
  • Position Input：左手或右手控制器位置。
  • Rotation Input：左手或右手控制器旋转。
  • Tracking State Input：左手或右手控制器追踪状态。

作用：

  • 用真实 VR 手柄的追踪数据驱动 Unity 中的手柄对象。

对当前项目的建议：

  • 必须保留。
  • UI 选择、点云点选、射线方向都依赖它。

7. Controller Visual

路径：

  • Left Controller/Left Controller Visual
  • Right Controller/Right Controller Visual

来源预置件：

  • Prefabs/Controllers/XR Controller Left.prefab
  • Prefabs/Controllers/XR Controller Right.prefab

作用：

  • 显示左右手柄模型。
  • 包括手柄主体、扳机、摇杆、按钮、触摸板等可视部件。

对当前项目的建议：

  • 开发阶段建议保留，便于判断手柄位置和朝向是否正确。
  • 实验阶段如果觉得干扰视觉，可以隐藏可视模型，但不要禁用手柄追踪和交互器。

8. Poke Interactor

路径：

  • Left Controller/Poke Interactor
  • Right Controller/Poke Interactor

来源预置件：

Prefabs/Interactors/Poke Interactor.prefab

主要脚本：

XRPokeInteractor

主要参数：

  • Interaction Layers：全部交互层。
  • Handedness：由实例或父级上下文决定。
  • Attach Transform：Poke Point。
  • Enable UI Interaction：启用。

子对象：

  • Poke Point
  • Poke Point Affordances

作用：

  • 支持近距离“戳/触碰”式交互。
  • 当手柄靠近 UI 或可交互物体时，用 Poke Point 作为触碰点。

参数解释：

  • Interaction Layers 决定它能触碰哪些交互层。
  • Attach Transform 是实际触碰点。
  • Enable UI Interaction 允许它触碰 Unity UI。

对当前项目的建议：

  • 如果 UI 面板放得比较近，可以使用。
  • 如果用户主要通过射线点击 UI，那么它不是最关键组件。

9. Near-Far Interactor

路径：

  • Left Controller/Near-Far Interactor
  • Right Controller/Near-Far Interactor

来源预置件：

  • Prefabs/Interactors/Left_NearFarInteractor.prefab
  • Prefabs/Interactors/Right_NearFarInteractor.prefab

主要脚本：

NearFarInteractor

主要参数：

  • Interaction Layers：全部交互层。
  • Handedness：左手或右手。
  • Allow Hovered Activate：禁用。
  • Target Priority Mode：0。
  • Enable UI Interaction：启用。
  • Block UI On Interactable Selection：启用。

作用：

  • 同时支持近距离和远距离交互。
  • 可以用于点击世界空间 UI，也可以用于选择 3D 可交互物体。

参数解释：

  • Interaction Layers 控制可交互目标范围。
  • Handedness 标识左右手。
  • Allow Hovered Activate 控制是否允许悬停激活。
  • Target Priority Mode 控制多个目标同时命中时的优先级。
  • Enable UI Interaction 允许点击 UI。
  • Block UI On Interactable Selection 表示正在选择 3D 物体时阻止 UI 交互。

对当前项目的建议：

  • 这是最值得保留的交互器。
  • 首页按钮、设置面板、质量评分面板、JND 操作面板都可以依赖它。
  • 将来做点云点选时，也可以先从这个交互器的射线逻辑入手，再按需要做自定义精确点选。

10. Teleport Interactor

路径：

  • Left Controller/Teleport Interactor
  • Right Controller/Teleport Interactor

来源预置件：

Prefabs/Interactors/Teleport Interactor.prefab

主要脚本：

XRRayInteractor

主要参数：

  • Interaction Layers：全部交互层。
  • Line Type：曲线或抛物线式射线。
  • Max Raycast Distance：30。
  • Hover To Select：禁用。
  • Enable UI Interaction：禁用。
  • Block UI On Interactable Selection：启用。

作用：

  • 专门用于传送。
  • 它不是普通 UI 点击射线。

参数解释：

  • Line Type 控制传送射线形状。
  • Max Raycast Distance 是传送射线最大距离。
  • Hover To Select 禁用表示不会仅靠悬停选择。
  • Enable UI Interaction 禁用表示传送射线不点击 UI。

对当前项目的建议：

  • 主观质量评价通常不需要传送。
  • 如果希望受试者固定在同一个观察位置，应禁用传送。

11. Gaze Interactor

路径：

Camera Offset/Gaze Interactor

来源预置件：

Prefabs/Interactors/Gaze Interactor.prefab

主要脚本：

XRGazeInteractor

状态：

  • 在 XR Origin (XR Rig) 中默认禁用。

主要参数：

  • Line Type：直线。
  • Max Raycast Distance：30。
  • Hover To Select：启用。
  • Hover Time To Select：1。
  • Enable UI Interaction：启用。

作用：

  • 用户看向某个 UI 或物体一段时间后，可以触发选择。

对当前项目的建议：

  • 暂时保持禁用。
  • 主观实验中用户会自然观察很多地方，如果凝视自动选择开启，容易产生误操作。
