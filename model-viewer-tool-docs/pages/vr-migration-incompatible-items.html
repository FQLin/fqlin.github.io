VR 项目不适用项迁移清单

本文档用于记录旧版 VR 点云质量评价项目和参考的普通 3D 项目中，哪些实现不适合直接迁移到当前 Unity 6000.4 + Oculus/XR Interaction Toolkit VR 项目中，以及每一项建议如何处理。

总体判断

旧版 VR 项目虽然已经带有 XR Origin，但仍混有不少桌面端实现，例如 Win32 文件选择框、鼠标触摸输入、手动多相机切换等。参考项目 AVersatilePointCloudProcessingPlatform 的代码结构更清晰，但它本质上是普通桌面 3D 项目，包含更多 Windows 桌面 API、StandaloneFileBrowser、外部进程调用、屏幕像素布局等逻辑。

迁移策略不应该是整段复制，而应该是：

  1. 保留实验业务逻辑，例如质量评价流程、JND 判断流程、点云读取、结果记录。
  2. 替换桌面交互层，例如文件选择、弹窗、鼠标控制、窗口按钮。
  3. 把 UI 和模型交互接到 VR 体系，例如 World Space Canvas、XRUIInputModule、TrackedDeviceGraphicRaycaster、XR Ray Interactor、Input Actions。

不适用项与解决方案

优先级不适用项旧项目/参考项目位置为什么不适合 VR建议解决方案当前新项目状态
P0Windows 原生文件/保存对话框旧项目：Assets/Scripts/LogUtil/FileUtils.cs 使用 Comdlg32.dll；StartPanel.cs 调用 LocalDialog.GetOpenFileName。参考项目：SettingPanel.cs、MenuButton.cs 使用 StandaloneFileBrowser.OpenFilePanel/OpenFolderPanel/SaveFilePanel这些 API 依赖 Windows 桌面窗口。Oculus 头显或 Android 平台无法使用，PCVR 中也会打断沉浸式体验抽象成 IPathPicker。当前阶段保留世界空间输入框手动填写路径；下一阶段做 VR 内文件/目录选择面板；如果只跑 PCVR，可把桌面选择器放进 #if UNITY_STANDALONE_WIN && !UNITY_ANDROID 的临时实现待处理。当前新项目 Browse/Save 暂未接真实 VR 文件浏览器
P0Win32 MessageBox 和桌面退出确认参考项目：Assets/Script/Common/Framework/Win32API.cs；SystemPanel.cs 调用 Win32API.ConfirmMessageBox 和 Application.Quit(0)VR 中没有传统桌面弹窗；弹出系统窗口会脱离头显交互；强制退出不利于实验恢复做一个 World Space AlertPanel/ConfirmPanel，用 XR 射线点击按钮。退出逻辑优先改成“返回 Home 场景”或“结束实验并保存”，真正退出只作为 PCVR 辅助按钮待处理。当前新控制器主要用日志/状态文本提示
P0鼠标、触摸、旧 Input 输入旧项目：MouseTouchController.cs 使用 Input.GetMouseButtonDown、Input.mousePosition、Mouse ScrollWheel；PlayerInputController.cs 使用 Input.GetTouch；ModelViewerControl.cs 是鼠标式模型控制VR 的主要输入来自头显、左右手柄、射线、抓取、扳机键和摇杆。鼠标/触摸逻辑不能代表 VR 操作用 XR Interaction Toolkit 的 Input Actions、XR Ray Interactor、XR Direct/Grab Interactor 替代。模型旋转/缩放建议单独写 PointCloudManipulationController，支持手柄抓取、摇杆缩放、双手缩放待处理。当前只完成 UI 样式和基础流程，模型 VR 操作还未迁移
P0Screen Space Overlay UI 和 StandaloneInputModule旧项目和参考项目场景中存在 m_RenderMode: 0 的 Canvas；普通桌面 EventSystem 通常使用 StandaloneInputModuleOverlay Canvas 是贴屏幕渲染，不在 VR 世界空间中，头显射线不能自然点击；StandaloneInputModule 面向鼠标键盘实验场景 UI 使用 World Space Canvas；Canvas 上挂 TrackedDeviceGraphicRaycaster；EventSystem 使用 XRUIInputModule；Canvas 放在场景根或 UIRoot 下，不放入 XR Origin 预制件内部部分完成。新项目质量评价/JND 场景已有 World Space Canvas 和 XR UI 组件方向，但仍需逐场景清理遗留 Overlay Canvas
P0手动多相机/桌面相机管理旧项目：CameraManager.cs 管理 leftCamera/rightCamera/uiCamera/singleCamera，并手动切换 cullingMask；参考项目：MainCamera.cs 控制主相机层级可见性VR 中左右眼相机由 XR 系统处理，不应该自己创建左右眼相机并手动启停；这可能破坏 XR 渲染和追踪使用 XR Origin 中的 Main Camera 作为唯一头显相机。需要隐藏/显示模型时，优先控制模型对象、Layer 或 Renderer，而不是切换多套 Camera。特殊对比需求再用可控的模型根节点和材质实现待处理。新项目已有 XR Origin，但旧相机控制逻辑不能直接搬
P1屏幕像素布局参考项目：QualityRatingScene/UI/Playing/PlayingPanel.cs 使用 Screen.width / 2 - 50 来计算模型/按钮布局VR 中没有稳定的“屏幕宽度”概念；UI 需要按世界空间距离、Canvas 尺寸和舒适视角布局用 RectTransform、Layout Group、固定世界单位、Canvas Scaler 配合 XR 射线交互。模型左右布局用世界坐标和可配置间距，不依赖像素宽度部分处理。新场景样式已在世界空间中复刻，但模型和按钮的舒适距离还需要实机调试
P1Environment.CurrentDirectory 和硬编码 Windows 路径参考项目：AppConfiguration.cs 使用 Environment.CurrentDirectory + "\\Result"；JND SettingPanel.cs 拼接结果路径；质量评价 SettingPanel.cs 写死 D:\项目\... 默认路径Unity 打包后当前目录不稳定；Oculus/Android 没有 Windows 盘符；硬编码路径换机器就失效输入资源路径由配置文件、StreamingAssets 或用户输入决定；输出结果使用 Application.persistentDataPath；开发期可提供默认测试路径，但必须放入 Editor/Windows 条件或配置文件部分处理。新项目已有 ExperimentPaths，但仍需统一所有默认输入/输出路径策略
P1外部可执行程序和阻塞式进程调用参考项目：HomeScene/MenuButton.cs 使用 Process.Start()、process.WaitForExit() 处理 PCL 工具头显端无法直接启动 Windows exe；WaitForExit 会阻塞 Unity 主线程，VR 中会造成卡死/眩晕点云预处理放到 VR 外部流程完成；或做 Unity Editor 工具；或改成异步后台服务。VR 应只读取已经准备好的点云和配置待处理。不建议迁移到运行时 VR 场景
P1Resources.Load 加载大型/动态点云旧项目：GameManager.cs 使用 Resources.Load(data.pathA/pathB)Resources 适合小型固定资源，不适合大体量点云和实验动态数据；打包体积、内存、路径管理都不理想点云文件从配置路径、StreamingAssets、Addressables 或持久化目录读取。运行时通过点云解析器生成 Mesh/GameObject已开始处理。新项目已迁移文件路径读取和 PointCloudModelFactory，不再依赖旧 Resources.Load 流程
P1桌面窗口系统按钮参考项目：Common/UI/System/SystemPanel.cs、质量评价 UI/System/SystemPanel.cs最大化、最小化、关闭窗口是桌面应用概念，VR 中没有对应窗口Home/实验场景只保留 VR 内导航按钮，例如 Back、Exit Experiment、Return Home。PCVR 调试版可以保留一个 Editor/Standalone 条件下的 Quit待处理。不建议搬迁窗口控制面板
P1旧版 InputField 直接承担大量配置输入旧项目和参考项目多个 SettingPanel.cs/StartPanel.cs 使用 UnityEngine.UI.InputFieldVR 中手柄输入文字很慢，输入路径尤其痛苦。InputField 可用，但不是理想交互当前学习阶段可以保留输入框，方便编辑器和 PCVR 调试；后续改为配置文件选择、预设下拉框、实验员编号短输入、虚拟键盘当前保留。需要后续做更适合 VR 的配置体验
P1静态全局配置和跨场景状态旧项目：GameManager/Global/单例；参考项目：AppConfiguration.PlayingSettings小项目可用，但多场景 VR 实验中容易残留状态，重复进入场景可能出现旧数据污染核心实验状态用场景内 Session 类承载；跨场景只传必要参数；加载新实验时显式 Reset已开始处理。新项目已有 QualityRatingSession、JndExperimentSession
P2旧场景中的 UnityEvent 持久引用参考项目和旧项目 Button 可能绑定旧脚本方法，例如旧 SettingPanel.Complete、旧输入框 ValueChanged直接复制场景时，缺脚本或方法签名变化会导致按钮失效，甚至隐藏编译/运行错误新项目统一由场景 Controller 在 Awake/Start 中绑定按钮事件，旧 PersistentCall 逐步清理部分完成。JND 场景已清理过部分旧引用，还需全场景复查
P2字符串形式协程和可疑协程写法参考项目：PlayingPanel.cs 中 StartCoroutine(nameof(PlayGroup))字符串协程不利于重构；如果目标不是 IEnumerator，运行时也容易出问题改为强类型 StartCoroutine(PlayGroup())，或直接拆成明确的状态机/计时器逻辑待处理。迁移播放流程时一起改
P2自定义点云渲染管线/Shader 兼容性参考项目：PointCloudRenderer、Pcx 相关 Shader/Buffer 渲染普通桌面渲染可行，不代表 XR/URP/Single Pass Instanced 下稳定；点云规模大时还涉及 VR 帧率先用当前 MeshRenderer/材质方式保证功能正确；再针对 XR 做性能测试；必要时改 URP/XR 兼容 Shader、GraphicsBuffer 或 GPU instancing待验证。当前新项目优先保证模型能显示和流程能跑
P2桌面相机距离和模型固定位置旧项目/参考项目模型坐标按普通屏幕视角摆放VR 中距离太近、太大、太偏都会造成不适或看不到；头显视角会随用户移动建立 ExperimentStageRoot，模型挂在固定世界锚点下，提供统一距离、缩放、左右间距配置，并支持重置视角部分完成。场景对象已复刻，后续需要实机舒适度调整

建议解决顺序

  1. 先解决 P0：World Space UI、XRUIInputModule、Win32 弹窗替换、桌面文件选择替换、旧输入替换。
  2. 再解决 P1：路径策略、结果保存、外部进程剥离、模型加载策略、VR 配置输入体验。
  3. 最后解决 P2：旧事件引用清理、协程重构、点云渲染性能、实机舒适距离。

下一步建议

建议下一步先做一个通用的 VR 弹窗系统 VRAlertPanel，用来替代旧项目和参考项目中的 AlertManager、Win32API.MessageBox 和 Debug.Log 提示。这个组件做完之后，质量评价和 JND 两个场景的校验错误、路径为空、实验结束提示都可以统一接入。

第二步再做路径选择策略：短期保留输入框和默认路径；中期加一个 VR 内部配置预设列表；长期再根据实际部署平台决定是否做完整 VR 文件浏览器。
