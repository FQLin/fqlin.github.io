NearFarInteractor 源码阅读笔记

本文档不是官方文档翻译，而是结合当前项目本地安装的 NearFarInteractor.cs 做的一份源码阅读笔记。

源码来源

  • Unity 包版本：com.unity.xr.interaction.toolkit 3.4.1
  • 源码文件：

Library/PackageCache/com.unity.xr.interaction.toolkit@4612b35e2aac/Runtime/Interaction/Interactors/NearFarInteractor.cs

1. 这份源码笔记关注什么

主要关注三类信息：

  • 官方文档里提到但不够直观的行为
  • 运行时到底会自动做什么
  • 近距、远距、UI 之间到底怎么切换

2. Awake() 里最先做的一件事

源码里 Awake() 的顺序很值得注意：

  1. 先 InitializeReferences()
  2. 再 base.Awake()

这意味着：

  • 它会尽量先把自己依赖的核心组件找齐
  • 然后再走基类初始化流程

这是一个比较关键的实现点，因为它确保了 attachTransform 在早期就能准备好。

3. 缺少核心组件时会自动补

InitializeReferences() 里做了三件核心事：

3.1 远距离 Caster

如果 farInteractionCaster 为空：

  • 先尝试找当前对象上已有的 ICurveInteractionCaster
  • 找不到就自动 AddComponent<CurveInteractionCaster>()

3.2 近距离 Caster

如果 nearInteractionCaster 为空：

  • 先找当前对象上已有的 IInteractionCaster
  • 但它会跳过那些同时也是 ICurveInteractionCaster 的组件
  • 也就是说，它不会把远距 Caster 误当成近距 Caster
  • 如果最终没找到，就自动 AddComponent<SphereInteractionCaster>()

这个细节说明：

官方已经考虑到了“远距 Caster 也实现了基础接口，所以不能乱认”的问题。

3.3 Attach Controller

如果 interactionAttachController 为空：

  • 先找当前对象上已有的 IInteractionAttachController
  • 找不到就自动 AddComponent<InteractionAttachController>()

最后还会执行：

  • attachTransform = interactionAttachController.GetOrCreateAnchorTransform()

也就是说：

附着锚点不是可有可无的，它会在初始化阶段被明确创建或拿到。

4. UI 交互不是单纯一个布尔值

enableUIInteraction 的 setter 里，不只是把布尔值改掉。
它还会调用：

  • RegisterOrUnregisterXRUIInputModule(m_EnableUIInteraction)

这说明：

  • UI 交互开关不只是“逻辑判断”
  • 它还会影响和 XRUIInputModule 的注册关系

也就是说，改这个值时，系统会同步处理 UI 注册状态。

5. OnEnable() / OnDisable() 做了什么

OnEnable()

如果 UI 交互开启，会执行 UpdateUIRegistration()。

OnDisable()

会做几件事：

  • 取消向 XRUIInputModule 的注册
  • 如果启用了 UI Toolkit 世界空间支持，也会从对应系统中注销
  • 调用 InitializeInteractor() 清空本轮交互缓存

这说明：

  • 它对 UI 注册状态的管理是比较完整的
  • 不是只在首次启动时注册一次就不管了

6. 每一帧的核心流程

在 PreprocessInteractor(UpdatePhase.Dynamic) 里，核心顺序是：

  1. InitializeInteractor()
  2. UpdateAnchor()
  3. DetermineSelectionRegion()
  4. EvaluateNearInteraction()
  5. EvaluateFarInteraction(newSelectionRegion)
  6. UpdateSelectionRegion(newSelectionRegion)
  7. 如启用 UI Toolkit 支持，再处理对应事件

这条顺序很重要，因为它告诉我们：

  • 先更新附着点
  • 再判断当前是 Near 还是 Far
  • 再依次评估近距和远距命中

7. selectionRegion 是怎么判断的

DetermineSelectionRegion() 的逻辑很直接：

  • 如果当前没有选择，返回 None
  • 如果有选择，则看 interactionAttachController.hasOffset
  • 有偏移就是 Far
  • 没偏移就是 Near

这意味着一个很关键的行为：

某个对象最开始可能是通过远距离选中的，但如果它被拉近到没有偏移，selectionRegion 会从 Far 变成 Near。

这也是官方文档里“Far 选中后可能变成 Near”的源码依据。

8. 近距和远距的优先关系

近距逻辑

EvaluateNearInteraction() 里，如果满足下面任一条件，就不会继续：

  • 没开启近距探测
  • 当前已经有选中对象
  • 近距 Caster 没找到有效 Collider

也就是说：

  • 近距逻辑更偏向“未选中时找手边目标”
  • 不是那种选中了还一直靠近重新抢目标的设计

远距逻辑

EvaluateFarInteraction() 里有两个关键条件：

  • 如果没开远距探测，且当前也不是 Far 选中，就不更新远距
  • 如果近距已经先找到有效目标，则直接不处理远距

这说明一个很重要的优先级规则：

同一帧里，如果近距先拿到有效目标，远距通常让路。

这也符合交互直觉：

  • 手边真有能抓的东西时，优先按近距处理
  • 不要让远处射线抢走焦点

9. 它会比较 2D UI 命中和 3D 命中

远距逻辑不是只看 3D Collider。

它还会：

  • 取当前 UI 的 RaycastResult
  • 计算 UI 命中距离
  • 计算 3D 命中距离
  • 比较两者谁更应该被处理

更容易理解地说：

它不是“只要打到 3D 就不管 UI”，而是会在 UI 和 3D 之间做优先级比较。

这对于带有 World Space UI 和 3D 模型同时存在的 VR 场景很重要。

10. 目前只支持一个有效目标

源码里有一个明确字段：

  • m_AllowMultipleValidTargets = false

并且注释写得很清楚：

  • 当前只支持一个有效目标
  • 未来可能再扩展为多个

这意味着：

  • 它内部虽然可能会暂存多个候选
  • 但最终对外主要还是按“单一有效目标”这个思路工作

11. 排序和过滤的一个细节

近距和远距目标注册时都会考虑 targetFilter。

一个值得注意的细节是：

  • 如果有 targetFilter，很多情况下排序会交给 filter
  • sortNearTargetsAfterTargetFilter 只适合“filter 本身不排序”的情况

这说明：

  • 这个选项不是默认都该开
  • 它是给进阶过滤逻辑准备的

12. 对项目实践最有价值的结论

综合源码，最值得记住的是这几条：

  1. NearFarInteractor 运行时确实会自动补默认组件
  2. 但项目里最好还是显式挂好，方便排查
  3. 它的 UI 交互开关会影响注册状态，不只是变量值
  4. 近距优先级通常高于远距
  5. 远距逻辑会同时权衡 UI 命中和 3D 命中
  6. selectionRegion 会随着对象被拉近而变化

13. 一句话结论

从源码看，NearFarInteractor 的设计重点不是“单纯打一条线”，
而是“用一套统一交互器，把近距、远距、UI、附着点和状态切换统筹起来”。
